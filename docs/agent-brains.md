# Agent Brains and Personalities

Which model ("brain") each agent runs on, why, and who each agent is. The `model:` line in each `.claude/agents/<name>.md` file sets the brain. Each persona is written into the agent's "Who you are" section.

## The rule

| Model | Used for | Count |
|---|---|---|
| **opus** | Judgment-heavy roles where a confident wrong answer is costly: orchestration and synthesis, cross-workstream QC, adversarial reasoning, regulatory interpretation, DCF and LBO judgment, regression auditing | 7 |
| **sonnet** | Most specialist reviewers that apply a well-defined checklist or skill to her work, and the interview coach, where speed matters for drilling | 12 |
| **haiku** | Fast, literal lookups only (IDs, endpoints, units, dates) | 1 |

Personality shapes tone only. Every agent still follows the sparring-partner rule in `CLAUDE.md` and its report template, whatever its voice.

## How the model setting behaves

- **Order of precedence** (from the official subagent docs): a model passed when the agent is called beats the file's `model:` line, which beats the `CLAUDE_CODE_SUBAGENT_MODEL` environment variable, which beats the parent conversation's model. The orchestrator is told **not** to pass a model when it calls experts, so each expert's file setting applies.
- **Nested calls:** experts called by the orchestrator run on their own `model:`, not on the orchestrator's, because every file sets one.
- **Same-family aliases:** `opus` and `sonnet` run on the version your session uses when it is in the same family; otherwise on the version the alias points to.
- **Overrides that ignore these settings:** `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` makes every agent run on one model. An `availableModels` allowlist that blocks a model substitutes another.
- **Checking:** while an agent runs, `/tasks` shows the model on its row.

## Changing a brain or a persona

Edit the `model:` line or the "Who you are" section in the agent's file, then update this table. Or ask `@agent-team-builder`, which keeps the files and this table in sync.

## Knowledge folders

Each agent reads `knowledge/<agent-name>/` before every answer. Each folder's `README.md` says what belongs there. The contents are reference material only, so the sparring-partner rule still applies.
